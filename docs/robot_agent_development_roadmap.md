# 面向真实机器人的 Agent 框架路线

## 1. 项目定位

本项目以现有 `self-test Agent` 为上层决策基础，逐步扩展为能够连接真实机器人的具身智能体框架。系统不让大模型直接控制电机、舵机或设备驱动，而是通过独立机器人网关提交高层动作，并根据真实反馈继续决策。

```text
用户目标
  -> Agent 决策层（LLM / GoalRunner / Verifier）
  -> 网关客户端（统一动作和反馈协议）
  -> 机器人网关（安全、状态、超时、取消、急停）
  -> ROS 2 / 厂商 SDK / 控制器
  -> 真实机器人
```

职责边界：

| 层次 | 主要职责 |
|---|---|
| Agent 决策层 | 理解目标、选择高层能力、根据反馈调整下一步 |
| 网关客户端 | 提交动作、查询状态、取消动作、请求急停、解析反馈 |
| 机器人网关 | 鉴权、安全检查、动作生命周期、资源管理、通信与审计 |
| 控制器与驱动 | 导航、轨迹规划、闭环运动控制和设备驱动 |
| 硬件 | 执行动作并产生传感器观测 |

## 3. 本项目与目标架构的对应关系

| 现有模块 | 当前定位 | 后续扩展 |
|---|---|---|
| `agent/execution/` | 动态目标执行器 | 接收机器人反馈，决定继续、修正或停止 |
| `agent/models/` | 模型接入层 | 支持不同真实大模型和多模态模型 |
| `agent/robot/tools.py` | LLM 高层能力入口 | 只暴露语义动作、状态、取消和急停 |
| `contracts/robot.py` | 统一数据协议 | 动作 ID、状态、进度、观测、错误和结果 |
| `agent/robot/client.py` | 网关客户端 | HTTP、Socket，后续可增加 ROS 2 客户端 |
| `robot_runtime/adapter.py` | 仿真/硬件适配边界 | 通过统一协议替换模拟器、Gazebo、ROS 2 或厂商 SDK |
| `robot_runtime/safety.py` | 执行端安全检查 | 与机器人本地控制器形成多层防护 |
| `robot_runtime/simulator.py` | 模拟执行器 | 在无硬件条件下验证完整动作生命周期 |
| `agent/scheduling/remote.py` | 通用远程服务执行器 | 连接外部软件服务，但不替代机器人专用安全网关 |
| `services/registry.py` | 服务白名单 | 把稳定服务名映射到受控 HTTP 地址 |

## 4. 分阶段开发路线

### 阶段 A：统一协议与动作生命周期

- 为每个动作分配唯一 `action_id`。
- 统一 `pending`、`running`、`succeeded`、`failed`、`cancelled`、`timed_out` 状态。
- 支持提交动作、查询状态、取消动作和急停。
- HTTP/Socket 客户端必须解析网关真实响应，不使用伪造状态。
- 模拟器实现相同接口，作为第一套可验证网关。

完成标准：同一套 Agent 工具可以操作模拟器，并能查询动作结果、取消动作和请求急停。

### 阶段 B：真实反馈闭环

- 标准化位姿、电量、障碍物、图像引用和设备错误。
- 增加独立 Verifier，根据目标和观测判断任务是否完成。
- GoalRunner 每次只根据最新真实反馈决定下一步。
- 处理无反馈、延迟、状态冲突、动作失败和通信中断。

完成标准：任务结果由实际观测决定，不由模型自行宣称完成。

当前进展：已实现阶段 B 的两级验收。`/robot-goal` 只开放高层机器人工具；第一级由 `RobotFeedbackVerifier` 检查网关 JSON、动作终态、停止状态、急停状态和图像引用。动作仍为 `pending` 或 `running` 时，模型必须继续查询同一 `action_id`，不能直接宣称完成。

感知侧已增加独立的模拟 HTTP 服务和统一 `Observation` 协议。`perception_check_path` 可返回路径畅通、存在障碍或传感器故障；GoalRunner 与普通 Agent 在后续移动前读取最新感知事件，只有 `path_clear=true` 时才允许继续。当前观察来自确定性模拟场景，尚未接入真实摄像头、视觉模型或 ROS 2 传感器 Topic。

第二级为无工具语义 Critic。它独立接收用户目标、实际工具参数、网关反馈和执行模型给出的结论，只返回结构化验收结果。参数或观测不满足目标时，原因和最小补充步骤会写回 `GoalRunner`，由执行模型继续修正。当前默认复用同一个模型后端进行单独的 Critic 调用，接口允许以后替换为不同模型。Critic 目前可以判断文本和数值化观测，尚不能读取图像引用中的真实视觉内容。

### 阶段 C：独立机器人网关

- 将网关作为独立进程运行，隔离 Agent 与硬件权限。
- 增加身份认证、动作授权、资源锁、心跳、看门狗和审计日志。
- Agent 退出、网络断开或动作超时时，网关能够进入安全状态。
- 保留独立物理急停和机器人本地安全控制器。

完成标准：关闭 Agent 进程不会导致机器人继续失控运动。

当前进展：已增加独立的异步 HTTP 网关 `robot_runtime/gateway_server.py`，用于验证真实进程边界。它实现动作提交与查询、`pending/running/terminal` 生命周期、单运动资源约束、幂等 `action_id`、取消、动作超时、通信空闲看门狗和急停。网关通过 `RobotRuntimeAdapter` 注入下层运行时，当前工厂提供 `simulated`；关闭网关会取消在途动作、发送停止命令并关闭适配器。该服务仅绑定本机回环地址，目前没有真实硬件鉴权、持久化控制账本或独立物理急停，因此仍属于开发验证网关。

### 阶段 D：ROS 2 或厂商 SDK 接入

- 先实现一个新的 `RobotRuntimeAdapter`，把统一高层命令映射为仿真环境或设备指令。
- 在 `execute_motion` 中接收取消事件、转发运行进度并返回终态，网关不估算设备的真实执行结果。
- 适配器将原生坐标转换为米制平面坐标：+x 为零航向，逆时针为正。
- 根据目标机器人选择 ROS 2、HTTP、Socket、串口或厂商 SDK。
- 连续传感器数据使用 ROS 2 Topic。
- 快速查询使用 ROS 2 Service。
- 可反馈、可取消的长任务使用 ROS 2 Action。
- 移动底盘优先接入 Navigation2，机械臂优先接入 MoveIt 2。

完成标准：只替换网关下层适配器，Agent 工具和目标执行器保持不变。

### 阶段 E：多模态、技能和多机器人

- 接入图像、深度、语音和环境地图。
- 将稳定动作组合沉淀为可复用机器人技能。
- 记录成功与失败轨迹，用于评估、检索和后续训练。
- 有明确需求后再增加跨机器人调度和共享记忆。

## 5. 安全原则

1. 大模型只能提出高层动作意图，不能直接写电机速度、寄存器或 GPIO。
2. Agent 侧校验不能替代机器人网关和本地控制器的安全限制。
3. 急停路径必须独立、优先、可重复调用，并在通信异常时保持有效。
4. 真实动作必须有有限超时、可查询状态和明确最终结果。
5. 所有真实硬件动作先经过单元测试、模拟器和受控现场测试。
6. 研究框架不能替代工业机器人认证安全系统。
